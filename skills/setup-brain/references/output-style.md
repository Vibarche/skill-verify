# Output style template

Build a concise `## Output style` section from the interview. Keep it under 15 lines, write it in English, and use exactly the heading `## Output style`.

Select only applicable lines and adapt the wording to the user's answers.

## Technical level

- Non-technical:

```markdown
- I am not technical. Make technical choices yourself and explain them in one plain sentence.
- Avoid jargon. Explain unavoidable technical terms in everyday words.
```

- Intermediate:

```markdown
- I understand basic technical concepts but am not a developer. Explain choices briefly.
- Give commands only when necessary, ready to copy, with a one-line explanation.
```

- Developer:

```markdown
- I am a developer. Technical detail is welcome, but keep it concise.
- Ask before major architecture or dependency decisions.
```

## Autonomy

- Autonomous:

```markdown
- Work autonomously. Stop only for sign-in, payment, irreversible actions, or a choice only I can make.
- Ask one question at a time when input is required.
```

- Step by step:

```markdown
- Show a short plan, wait for approval, then execute each step and report what changed.
```

## Replies

```markdown
- Reply in <language>, <short and direct | detailed>. End with what was done and any action required from me.
```

## Safety

```markdown
- Never <user-specified restricted action> without showing it to me first.
```
