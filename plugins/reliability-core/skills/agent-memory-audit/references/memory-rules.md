# Memory rules

- Keep one authoritative fact in one file.
- Every durable decision needs a date, a decision, and a reason.
- Record rejected alternatives when they would otherwise be reconsidered.
- Use `About.md` for current project state; use `Roadmap.md` only for open work.
- Use `notes/journal/` for session history, not for authoritative project facts.
- Do not store secrets, credentials, private customer data, or environment values in memory files.
- Update the relevant memory file at the end of a meaningful work session.
- Treat a contradiction between two decisions as critical until resolved.
